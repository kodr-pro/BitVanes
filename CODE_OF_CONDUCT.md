# Code of Conduct

Bitvanes prioritizes technical accuracy, clear reasoning, and working code. We welcome contributors who want to build solid software, solve hard problems, and collaborate without bureaucratic overhead.

## Principles

1. **Be Correct, Not Performative**
   We care about whether the code works, the architecture is sound, and the logic holds up. Technical feedback is about the work, never the person. Expect direct feedback, and feel free to push back with benchmarks, documentation, or verifiable logic.

2. **Respect the Signal-to-Noise Ratio**
   Everyone's time is limited. When submitting issues or pull requests, provide clear context: minimal reproduction steps, relevant logs, and the rationale behind your design choices. Clear communication helps get your code reviewed and merged faster.

3. **Substance First**
   We value candid, substantive discussions over polished corporate pleasantries. You don't need to walk on eggshells, but keep the focus strictly on the problem at hand, the code, and the technical trade-offs.

4. **Maintainer Standards**
   Contributions containing unverified automated slop, covert telemetry, licensing conflicts, or bad-faith disruption will be rejected. 

## Collaboration & Governance

Project maintainers have final discretion over technical architecture and PR merges. If you bring good code, clear thinking, and an appetite for building reliable systems, you are always welcome here.
